# practice-translator

A workflow for translating difficult-to-explain creative, embodied, or interdisciplinary practices into clearer audience-facing language while preserving nuance, integrity, and emotional truth.

## Project context

Practitioners often hold deep knowledge that resists plain description: somatic work, improvisational craft, research-led art, ritual, facilitation, sensing-based methods. The aim here is to help that knowledge meet an audience (funders, collaborators, participants, the curious public) on its own terms — not to simplify it into something it isn't.

## Stack & commands

This project primarily uses Markdown files and Claude Code within VS Code.

Files:

- `CLAUDE.md` — general workflow philosophy and conventions
- `SKILL.md` — operational workflow instructions
- `trigger-test.md` — trigger validation tests

Commands:

- Use Claude Code within VS Code to draft, revise, and test workflows.
- Save files regularly using `Cmd + S`.
- Use natural-language prompts to test skill invocation.

## Conventions

- Use British English.
- Prefer clear, concrete language over abstract framing.
- Preserve the practitioner’s own voice where possible.
- Use specific examples rather than broad claims.
- Match language to the intended audience.
- Avoid unnecessary jargon and creative-industry clichés.
- Offer multiple framing options where useful instead of a single “perfect” version.

## Do's

- Stay close to the practitioner’s original meaning.
- Preserve complexity where it genuinely matters.
- Use concrete examples and sensory language where possible.
- Adapt communication to different audiences.
- Flag where meaning may have been lost in translation.

## Don'ts

- Do not rely on buzzwords or vague creative-industry language.
- Do not overclaim emotional or transformative outcomes.
- Do not flatten nuanced practices into generic marketing copy.
- Do not prioritise sounding impressive over being understandable.
- Do not speak about the practice in ways the practitioner would not recognise.

## Working approach

When drafting or revising:

1. Ask what the practitioner wants the reader to _do, feel, or understand_ — not just what the text should "say".
2. Offer 2–3 distinct register options where useful, rather than one polished default.
3. Flag any phrasing where nuance may have been lost in translation, and propose alternatives.
4. Treat the practitioner as the final authority on whether a translation is faithful.

## External references

Useful references may include:

- practitioner notes or transcripts
- workshop reflections
- artist statements
- website copy
- funding applications
- rehearsal/process documentation
- audience descriptions
- examples of language the practitioner feels accurately represents the work

When references conflict, prioritise clarity and fidelity to the practitioner’s intent.
